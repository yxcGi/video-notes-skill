# v3 定稿标注样式规范 + 防呆核验清单

样式经三轮用户验收定型（v1 红底标签压图 ❌ → v2 图注外置图上只剩编号 ❌ → v3 ✅）。改样式属于"改 skill 本体"，须用户点头。

## 样式规范

- **红框**：3px 细线，精确框住目标控件/区域，不带填充。
- **标签**：红底（RGB 225,30,30）圆角矩形 + 白字（PingFang 28px），文字含序号与完整说明（如 `① 速度大小 0.4 m/s`）——只有编号没文字是 v2 被否的原因。
- **落点**：引擎按"分块像素方差"自动挑空白低信息区，右侧优先；标签间、标签与红框禁止互压；允许轻微压住图内低信息内容（用户明确接受此妥协）。
- **引线**：标签与框不相邻时画 2px 红线 + 框端 4px 圆点。
- **画布**：不扩边、不加图注条，一切元素在原分辨率画布内。
- **无框整图说明**（notes 字段）：用于"整图即主题、指不到某个具体控件"的图，引擎全图搜最空处放置。两类典型：① 云图/网格全景；② **操作结果展示图**（切完一半的模型、移动到位后的边界、生成好的计算域）——这类图要说的是"整体变成了什么样"，硬套红框只能框住半个视口，反而不如一句整图说明干净。
  判据：**能指到具体控件/局部区域 → 用 boxes；只能说"整张图现在是这个状态" → 用 notes。** 同一集里两种混用是正常的，不必强行统一。
- 长说明（推导、原理、多行上下文）不进标签，写进笔记正文。

## 标签文字规范

- 一句话一个动作/一个值，序号 ①②③ 与操作顺序一致；
- 按钮名、参数值保持界面原文（英文按钮不翻译）；
- 每图标签 ≤6 条，超了说明该图该拆。
- **长度 ≤14 个全角字符**（含序号）。标签宽度直接决定它能落在哪：写长了引擎只能往大片空白区扔，往往正好盖住有用信息。
- **序数、口诀、推导、原理一律下沉到笔记正文**，标签只留「动作 + 值」。
  反例：`① 模型第 4 项 k-epsilon（2 eqn）` —— 标签被推到列表上方，恰好盖住前 3 项，读者反而数不出"第 4 项"。
  正例：`① 模型选 k-epsilon (2 eqn)`，"432 口诀对应哪三项"写进正文表格。

## 坐标标定工序

1. 全分辨率精读源帧（不要在缩略图上估坐标）；
2. 记录像素坐标 [x1,y1,x2,y2]，框边留 2~4px 呼吸空间；
3. 同一面板多个目标时按视觉顺序编号，与笔记正文引用一致。

## 防呆核验清单（渲染后逐项过）

1. **帧内容对不对**：定点抽帧可能撞 UI 过渡瞬间（对话框只画一半、PPT 翻页中）——对话框/弹窗类关键图必须全分辨率单独核验"红框framed的内容 = 标签说的内容"；总览缩略图查不出这个（material-db 事故：v2/v3 连续两版带病通过总览自检）。发现错帧：±0.5~2s 微调时间戳重抽重标。
2. **图内数值对不对**：凡标签引用了图内数值（尺寸、参数、计数），必须全分辨率确认**该数值真的就在图里**。演示"键入数值"的镜头有两种翻车方式，都不会破坏帧本身、总览一律查不出：
   - 输入框里是鼠标拖动的**实时中间值**（P19 事故：画圆标"152.4"图上却是 21.26mm、拉动标"355.6"图上却是 62.62mm）；
   - 帧停在讲师**开始输入之前**，显示的还是软件默认值（P21 事故：讲师口述"半径 3000"，该秒的帧上是默认 977.93mm）。

   **根因是同一个：讲师"说出"数值的时刻 ≠ 该值出现在界面的时刻，口述总是先于输入 5~20 秒。**
   补抽策略：凡转写稿里出现具体数值的时间点，**同时抽「口述时刻」和「口述后 10~20 秒」两处**，一律以后者核对数值；两处都不对就沿时间轴继续找结果帧。此类坑已三次中招。
3. **序号是讲解序不是重要性序**：渲染后回读一遍 ①②③，确认它跟着内容的固有顺序走，而不是按红框的显眼程度或图上的视觉动线排。两类图判据不同：
   - **操作图**用**动作顺序**（先点工具 → 再拖尺寸 → 再切换输入框）；
   - **说明图**（无动作，只讲状态/因果）用**讲解顺序**：先主干后例外、先结论后限定。反例：车轮图标成 ①保留的凸台 ②轮毂已填平——读者会先读到例外再读到主干，应交换。
   规范里早有这条，仍然是实操中最容易忘的一条（已二次复现）。
4. **序号链里只放主线元素**：①②③ 会被读者默认为"先后顺序"，所以序号链**只能容纳同一条动作/因果主线上的元素**。界面里的**并列项、旁例、备选做法**即使值得标，也必须用**无序号标签**、并加「另一规则 / 另一种做法」这类前缀与主链区分。
   反例：P20 强力选择图标成 ①选择页 ②圆角可批量选 ③特征-凹陷 ④一键选中 ⑤计数——②只是讲师顺带举的另一个例子，却被读成 ③ 的前置步骤，用户看完图来问"为什么先选圆角再选凹陷"。改法：② 脱出序号链改为无序号旁注，主链收敛为 ①选择页 ②特征-凹陷 ③一键选中 ④计数。
   这是第 3 条的第三种失效形态——前两次是序号排错，这次是**不该进序号链的东西进了序号链**。
5. **标的是不是讲师讲过的**：逐条对照转写稿，界面里存在但视频没提的对象不该有红框（详见 SKILL.md 质量红线）。
6. **中文渲染**：引擎在渲染前会对所有标签逐字符做 .notdef 指纹体检，缺字形直接报错并指名字符与图名——**看到这个报错就换字符**（如 Ø→φ）或换字体，不要绕过。注意不能用 `getbbox()` 自行判断字形有无，.notdef 方框本身就有 bbox。
7. **压盖检查**：标签是否压住关键 UI 信息；引线是否交叉（交叉则调整框的传入顺序，自上而下）。
8. **总览终检**：`contact_sheet.py` 全部成图一屏过一遍（查漏、查错位、查风格不一致），但记住它只兜底宏观问题（见第 1、2 条）。
9. **不要忽略 ⚠️ 压盖告警**：引擎找不到空位时会降级压盖并打印告警。看到告警必须回去缩小该图红框（框应精确框住控件，不是整个面板）或精简标签，不能放着不管。
