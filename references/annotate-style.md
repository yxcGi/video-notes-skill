# v3 定稿标注样式规范 + 防呆核验清单

样式经三轮用户验收定型（v1 红底标签压图 ❌ → v2 图注外置图上只剩编号 ❌ → v3 ✅）。改样式属于"改 skill 本体"，须用户点头。各条规则的事故出处见 `lessons-archived.md`，此处只留规则与根因。

## 样式规范

- **红框**：3px 细线，精确框住目标控件/区域，不带填充。
- **标签**：红底（RGB 225,30,30）圆角矩形 + 白字（PingFang 28px），文字含序号与完整说明（如 `① 速度大小 0.4 m/s`）——只有编号没文字是 v2 被否的原因。
- **落点**：引擎按"分块像素方差"自动挑空白低信息区，右侧优先；标签间、标签与红框禁止互压；允许轻微压住图内低信息内容（用户明确接受此妥协）。
- **引线**：标签与框不相邻时画 2px 红线 + 框端 4px 圆点。
- **画布**：不扩边、不加图注条，一切元素在原分辨率画布内。
- **无框整图说明**（notes 字段）：用于"整图即主题、指不到具体控件"的图。两类典型：① 云图/网格全景；② 操作结果展示图（切完的模型、生成好的计算域）。判据：**能指到具体控件 → boxes；只能说"整张图现在是这个状态" → notes**；同一集混用正常。
- 长说明（推导、原理、多行上下文）不进标签也不进 notes，写笔记正文。

## 标签文字规范

- 一句话一个动作/一个值；按钮名、参数值保持界面原文（英文不翻译）；每图 ≤6 条，超了拆图。
- **长度 ≤14 全角字符**（引擎超长自动告警）。标签宽度决定落点，写长了会被扔进大片空白区、恰好盖住有用信息。
- **序数、口诀、推导一律下沉正文**，标签只留「动作 + 值」。

## 坐标标定工序

1. 全分辨率精读源帧（不在缩略图上估坐标）；细环/窄条类目标顺其走向取**扁框贴合**，标定完自问"框内面积占比最大的是不是目标"；
2. 记录像素坐标 [x1,y1,x2,y2]，框边留 2~4px 呼吸空间；
3. 同一面板多目标按视觉顺序编号，与笔记正文引用一致；
4. **精读一张就立刻写这张的 boxes 配置**——批量精读后统一落笔，坐标在记忆里必然串（P22 抄错事故）；
5. **每条标签写 `ev` 字段**（转写稿时间戳，如 `"ev":"26:07"`）。**写不出依据的对象一律不进 boxes**——下沉正文并注明「视频未展开讲解」。这是红线「只标讲师讲过的」三度复发后的强制手段，引擎对缺 `ev` 的标签自动告警。

## 防呆核验清单（渲染后逐项过）

1. **红框-内容一致性**：对话框/弹窗类、标签引用图内数值类的成图，必须**全分辨率逐张**核验（缩略总览一律查不出）。两种失效形态，六次中招：
   - UI 过渡瞬间（对话框半画、翻页中）→ ±0.5~2s 微调重抽；
   - **口述先于输入 5~20s**——该秒输入框是拖动中间值或软件默认值。补抽策略：数值时间点同时抽「口述时刻」与「+10~20s」，一律以后者核对。
2. **序号语义**：①②③ 会被读者默认为先后顺序，五次中招。三条判据：操作图＝动作顺序；说明图＝讲解顺序（先主干后例外）；**并列项/旁例/备选**用无序号标签 +「另一规则」前缀，不进主链。落笔前自问：**这几条能调换顺序吗？能调换就别编号**。
3. **标注依据核查**：缺 `ev` 告警必须处理；抽两条 `ev` 回转写稿验真。面板/选项类的图最容易从"复现讲师讲了什么"滑向"把面板项标全"，格外警惕。
4. **中文渲染**：引擎渲染前逐字符做 .notdef 指纹体检，缺字形直接报错——换字符（如 Ø→φ）或换字体，不要绕过；不能用 `getbbox()` 自判，.notdef 方框本身就有 bbox。
5. **告警零容忍**：压盖 / 标签超长 / 缺 ev / 引线穿框 / notes 超宽，五类引擎告警全部处理完才算过。压盖→缩框（框控件不框整面板）或精简标签；引线穿框→调两框相对位置或其一改 notes。
6. **总览终检**：`contact_sheet.py` 全部成图一屏过（查漏、查错位、查风格），但它只兜宏观问题——第 1 条那类必须全分辨率。
